Stow: Photo & File Organizer — Offline AI

Offline AI that tidies your PC — and never moves a file without asking.

Stow reads the folders you give it, works out where everything ought to go, and shows you the complete list of every change it proposes. Only when you press the button does anything move.

It runs entirely on your PC. No account, no server, no telemetry, no ads. The AI models are downloaded once and run on your own CPU — no file, file name, photo, document or search phrase ever leaves the machine.

The backlog

Your filing system did not fail. Life happened.

A Downloads folder with four thousand things in it. A Pictures folder holding three phones, two cameras and a decade of screenshots. Folders called “Holiday 2019”, “Copy of holiday” and “holiday (final)”, and no way to tell which is which.

Doing it by hand works, but nobody finishes. Cloud services will do it for you — by uploading your entire personal library to somebody else’s computer. Scriptable tools do exactly what you tell them, if you are willing to learn a rule syntax and test it on a copy first. And all of them, at the moment of truth, ask you to trust that the operation about to run across ten thousand files is the one you meant.

Nothing has moved yet

The preview is the actual product

You never find out what Stow decided by watching it happen. You find out by reading a table, before anything moves, in which every single file has a row, a destination, and the name of the rule that claimed it. If it is wrong you close the screen — and nothing has happened.

Untick any row you would rather leave alone. Filter the list. Export the whole plan to CSV or HTML and check it in a spreadsheet at your desk. Alongside it sits the rejection list: everything the validator refused, each with a readable reason — because “why was this file left alone” is exactly the question a preview exists to answer.

By design

Five rules the whole application is built on

Nothing leaves the PC

Not the files, not their names, not the index, not the embeddings, not the face data, not a crash log. There are exactly two network operations in the entire application, and you must start both of them deliberately.

Nothing happens without a preview

Every operation that touches a file — a one-click preset, a rule the language model wrote, a batch rename — goes through the same pipeline and arrives at the same preview screen. There is no quick path that skips it.

Nothing is deleted or overwritten

The engine only moves files, renames them and creates folders. Removal exists in exactly one place — the duplicate finder — and it goes through the Windows Recycle Bin, which survives Stow being uninstalled.

Everything is reversible

Every operation is written to a journal before it is carried out. That journal powers the undo button, recovers the app if the machine loses power mid-run, and knows afterwards which folders it emptied.

The models propose, code decides

The language model never sees your file list and never performs an operation. It emits rules. Ordinary auditable code applies them to every file, and an independent validator re-checks every destination it produced.

Five ways to describe what you want

They all converge on exactly the same preview.

1

Ready-made presets

Six one-click options: by file type, by year and month, by year, by type then year, screenshots moved aside, or by camera. Five of them work without opening a single file, so Stow is useful before any model is downloaded.

2

Describe it in your own words

“Move everything to do with invoices into an Invoices folder.” A local language model turns the sentence into rules. It receives a summary of your library — counts, extensions, date range, folder names — never the file list. There is no code path that would give it one.

3

Continue the system you already have

Stow reads the structure back out of your folder tree and writes rules that continue it. The analysis is evidence-based: a folder called 2019 only counts as a year folder if the files inside it are actually from 2019. No model, no download.

4

Build the rules yourself

When a file looks like this, put it in that folder. Rules run top-down, first match wins. Conditions cover extension, name, path, size, dates, dimensions, labels, people, places and visual similarity; destinations take fill-in tokens like {{year}}, {{month_name}} and {{camera}}.

5

Save it as a recipe

Any ruleset that reached a preview can be named and kept, run again, or handed to a watched folder. Saving grants it no privileges: it is recompiled, re-gated and re-validated on every run, and still arrives at a preview you have to approve.

One button puts everything back

History lists the last twenty things Stow did, newest first, and every one of them can be reversed exactly. After any organize a bar appears at the top of the window with a one-click undo — it is never buried in a menu.

Undo is deliberately not symmetrical with execution. Where execution stops at the first failure, undo attempts every operation and reports problems together, because halting halfway through a restore would strand you between two states. Moving files out of a folder empties it, and Stow is the only thing that knows which folders those were — so afterwards it offers to clear them away, and does no more than offer.

Finding things again

Everything here reads the index Stow already built, so most of it costs nothing to look at.

Search your files

A small documented syntax: kind:image, ext:pdf, size:>10mb, older:1y, in:Downloads, tag:work, text:“boiler warranty”, and a leading minus to exclude. It works fully even when Stow is not allowed to open your files.

Search photos by what is in them

Type “dog on a beach” and get your beach photos, whether they are called IMG_4821.jpg or anything else. Images are read, encoded locally into a vector, and released — the pictures themselves are never copied or retained.

See what is taking up the room

Totals by kind of file, your fullest folders counted all the way down, and your largest single files. Every finding carries the search that produced it, so “18 GB of videos nobody has opened in three years” hands you the exact query to act on.

Places and people

Photos group by where they were taken, and — only if you opt in — by which faces resemble one another. This is grouping by similarity, not identification: there is no identity database and no capability to determine who somebody is. You supply every name.

Labels

A word of your own — “work”, “taxes”, “holiday” — attached to any file you want to keep track of. Labels live in Stow’s index, so your files are never renamed or altered, and they work in every privacy mode.

Duplicates, including whole folders

Identical files are grouped by content, wherever they live and whatever they are called. So are identical folders — names take no part in the comparison, so “Holiday 2019” and “Copy of holiday” are the same folder if their bytes are. That is usually where the real space is.

Near-identical photos are caught too, using the same embeddings as photo search, so re-compressed and resized copies are found even though their bytes differ entirely. Four fully deterministic policies choose which copy to keep — best quality, oldest, newest, or whichever lives in a folder you nominate — and each choice comes with its reason. Nothing is deleted; spare copies go to the Recycle Bin.

Three more things it does

Batch renaming

Replace text, number a series, add a prefix or a suffix, fix capitalisation, strip a fragment. A rename is an ordinary ruleset whose destination is the file’s own folder — so it gets the same preview, the same validator and the same undo as everything else.

Watched folders

Files arriving in a watched folder are noticed and staged for review, optionally matched against a saved recipe. What it deliberately does not do is act: an organizer that quietly moved files in the background would be a much less trustworthy product, however convenient.

Keeping files together

A camera RAW is meaningless without its JPEG; a subtitle is no use without its video. A pass between the engine and the validator keeps companions together — conservatively, because a shared name prefix alone is not enough to prove two files belong to each other.

No account · no server · no telemetry

Privacy is the shape of the product, not a policy bolted onto it

There is no account, no backend and no cloud database — so there is nothing to breach, nothing to subpoena, and nothing for the developer to delete on your behalf. The developer receives no data from the application at all.

Everything Stow derives lives in one folder, deliberately kept outside cloud-synced locations so the index is never copied to the cloud by file sync or Windows backup. You can export the entire index to CSV and read it, erase face data on its own, erase stored document text on its own, or throw the whole index away and rebuild it. None of that touches a single one of your actual files.

Four models, none of them shipped inside the installer

Each is downloaded on first use of the feature that needs it, only after you have been shown the size and agreed, and each is verified against a SHA-256 hash pinned in the source. Every download URL is pinned to an immutable upstream commit, so the bytes fetched are always the bytes the hashes were taken from.

Declining leaves a fully working product: the presets, the manual builder, the convention learner, search, the space report, labels and duplicate detection need no models at all. Inference runs on the CPU via ONNX Runtime — no NPU or GPU provider is registered, and the application does not use the AI models built into Windows.

What Stow is not

  • Not a cloud photo service. It will not back anything up, sync anything between machines, or put a copy of your library anywhere but your own disk.
  • Not a duplicate remover that empties itself. Nothing is destroyed; the most it will ever do is put spare copies in the Recycle Bin at your request.
  • Not an automation daemon. It will notice files arriving in a watched folder, but it will not file them while you are not looking.
  • Not a black box. Every proposal comes with the rule that produced it, every rejection with an explanation, and the entire plan can be read in a spreadsheet before a single file moves.

Who it is for

The person with a Downloads folder that has become a landfill and a Pictures folder holding a decade of three different phones. The person who set up a filing system in 2019, kept it beautifully for four months, and would like the last five years put away the same way. The photographer who needs RAW and JPEG to stay together and needs to find the near-duplicates without uploading forty thousand images to anybody. And, running through all of them, the person who is not willing to send their personal files to a company’s servers in order to tidy them up.

Honest limits

Inference is CPU-only, so the first indexing pass over a large library is slow, and it is deliberately throttled further while running in the background. Model output can be wrong: a misread instruction produces an incorrect plan, which is precisely why the preview and the undo journal exist and why nothing is ever applied unattended. Face grouping works on resemblance alone and can group two people who look alike, or split one person across several groups.
