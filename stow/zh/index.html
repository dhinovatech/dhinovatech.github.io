Stow：照片与文件整理工具

离线 AI 帮你整理电脑——而且从不擅自移动任何文件。

Stow 读取你指定的文件夹，判断每样东西应该放在哪里，并把它建议的每一处改动完整列给你看。只有你按下按钮，才会有东西真正移动。

它完全运行在你自己的电脑上。没有账号，没有服务器，没有遥测，没有广告。AI 模型只下载一次，在你自己的 CPU 上运行：任何文件、文件名、照片、文档或搜索词都不会离开这台机器。

The backlog

不是你的归档方法失败了，只是生活插了进来。

一个塞了四千样东西的下载文件夹。一个装着三部手机、两台相机和十年截图的图片文件夹。名叫「假期 2019」「假期的副本」「假期（最终）」的文件夹并排躺着，根本分不清哪个是哪个。

手动整理是可行的，但没人能收尾。云服务愿意替你做——代价是把你整个私人库上传到别人的电脑里。可写脚本的工具会精确执行你的指令，前提是你愿意学一套规则语法，并且先在副本上试一遍。而所有这些工具，在关键时刻都要求你相信：即将扫过一万个文件的那次操作，正是你想要的那次。

Nothing has moved yet

预览本身就是这个产品

你永远不是通过旁观执行过程来得知 Stow 做了什么决定的。你是在任何东西移动之前，通过读一张表格知道的：表里每一个文件都有自己的一行、一个去向，以及认领它的那条规则的名字。如果不对，关掉这个界面就行——什么也没发生。

By design

支撑整个应用的五条准则

没有任何东西离开这台电脑

文件不会，文件名不会，索引不会，向量表示不会，人脸数据不会，连崩溃日志也不会。整个应用里只有恰好两次网络操作，而且两次都必须由你主动发起。

没有预览就不会发生任何事

任何触及文件的操作——一键预设、语言模型写出的规则、批量重命名——都走同一条流水线，抵达同一个预览界面。没有任何绕过它的捷径。

从不删除，也从不覆盖

引擎只做三件事：移动文件、重命名、新建文件夹。删除只存在于唯一一处——重复文件查找——并且经由 Windows 回收站，而回收站在 Stow 被卸载之后依然存在。

一切都可撤销

每一次操作在执行前都会先写入日志。这份日志支撑着撤销按钮，在机器中途断电时让应用得以恢复，并在事后知道哪些文件夹被腾空了。

模型只提议，由代码决定

语言模型从不查看你的文件清单，也从不执行任何操作。它产出的是规则。普通的、可审计的代码把这些规则套用到每个文件上，再由一个独立的校验器重新核对它生成的每一个去向。

描述你想要什么的五种方式

它们最终都汇入完全相同的那一个预览。

1

现成的预设

六个一键选项：按文件类型、按年和月、按年、先按类型再按年、把截图挪到一边、按相机。其中五个无需打开任何一个文件就能工作，所以在下载任何模型之前，Stow 就已经能派上用场。

2

用你自己的话说出来

「把所有跟发票有关的东西挪到发票文件夹里。」本地语言模型会把这句话变成规则。它拿到的是你这个库的摘要——数量、扩展名、日期范围、文件夹名称——而绝不是文件清单。代码里根本不存在把清单交给它的那条路径。

3

接着你已有的那套方法往下做

Stow 从你的文件夹树里把既有结构读回来，写出延续它的规则。分析基于证据：一个名叫 2019 的文件夹，只有当里面的文件确实来自 2019 年时，才算得上是年份文件夹。不需要模型，也不需要下载。

4

自己动手搭规则

当一个文件长这样，就把它放进那个文件夹。规则自上而下执行，第一条命中的胜出。条件涵盖扩展名、名称、路径、大小、日期、图像尺寸、标签、人物、地点和视觉相似度；去向支持 {{year}}、{{month_name}}、{{camera}} 这样的占位写法。

5

存成一份配方

任何走到过预览的规则集，都可以命名保存、再次运行，或者交给一个受监视的文件夹。保存并不会赋予它任何特权：每次运行都会重新编译、重新受限、重新校验——并且依旧会抵达一个需要你批准的预览。

一个按钮把一切放回原处

历史记录按时间从新到旧列出 Stow 做过的最近二十件事，其中每一件都能被精确还原。任何一次整理之后，窗口顶部都会出现一条横栏，一键即可撤销——它从不被埋在菜单深处。

撤销与执行故意不对称。执行会在第一次失败时停下，而撤销会尝试每一个操作，并把问题汇总报告，因为在还原到一半时停下，会让你卡在两种状态之间。把文件移出某个文件夹会让它变空，而只有 Stow 知道那些是哪些文件夹——所以事后它会提议帮你清掉，也仅止于提议。

把东西重新找出来

这里的一切读取的都是 Stow 早已建好的索引，所以看一眼几乎不花什么代价。

搜索你的文件

一套小而有文档的语法：kind:image、ext:pdf、size:>10mb、older:1y、in:Downloads、tag:work、text:「热水器 保修」，以及在前面加减号表示排除。即便你没有允许 Stow 打开你的文件，它也能完整工作。

按照片里有什么来找照片

输入「海滩上的狗」，就能得到你的海滩照片，不管它叫 IMG_4821.jpg 还是别的什么。图像被读取、在本地编码成向量，然后释放：照片本身从不会被复制或留存。

看清到底是什么占了空间

按文件种类的总量、一路数到最深处的最满文件夹，以及单个体积最大的文件。每一条发现都随身带着产生它的那句搜索，于是「三年没人打开过的 18 GB 视频」直接把可以据以行动的查询递到你手上。

地点与人物

照片会按拍摄地点归拢，并且——只有在你主动开启时——按哪些面孔彼此相像来归拢。这是按相似度分组，不是身份识别：没有任何身份数据库，也没有任何判定某人是谁的能力。所有名字都由你来填。

标签

你自己定的一个词——「工作」「税务」「假期」——贴在任何你想盯住的文件上。标签存在 Stow 的索引里，所以你的文件永远不会被改名或改动，而且在任何隐私模式下都能用。

重复项，连整个文件夹也算在内

内容相同的文件会按内容归为一组，无论它们躺在哪里、叫什么名字。相同的文件夹也一样：名称完全不参与比较，所以只要字节一致，「假期 2019」和「假期的副本」就是同一个文件夹。真正的空间通常就藏在这里。

近乎相同的照片同样会被找出来，用的是与照片搜索相同的向量表示，因此重新压缩、改过尺寸的副本即使字节完全不同也能被发现。四种完全确定性的策略决定保留哪一份——最佳画质、最旧、最新，或者位于你指定文件夹中的那一份——每个选择都附带理由。什么都不会被删除；多余的副本进回收站。

它还会做的三件事

批量重命名

替换文本、给一组文件编号、加前缀或后缀、统一大小写、去掉某一段。重命名不过是一套去向为文件自身所在文件夹的普通规则集——因此它享有和其他一切完全相同的预览、相同的校验器和相同的撤销。

受监视的文件夹

落进受监视文件夹的文件会被察觉并列入待审阅，必要时还会与已保存的配方比对。它刻意不做的事是「动手」：一个在后台悄悄搬动文件的整理工具，无论多方便，都会是个可信度低得多的产品。

让该在一起的文件待在一起

相机 RAW 离了配对的 JPEG 就没有意义；字幕离了视频也毫无用处。引擎与校验器之间的一道处理会让伴随文件一同移动——但很谨慎，因为仅仅共享一个文件名前缀，还不足以证明两个文件属于彼此。

No account · no server · no telemetry

隐私是这个产品的形状，而不是事后拧上去的一纸条款

没有账号，没有后端，没有云端数据库——因此没有什么可以泄露，没有什么可以被依法调取，也没有什么需要开发者代你删除。开发者从这个应用收不到任何数据。

Stow 推导出的一切都存放在同一个文件夹里，并且被刻意放在云同步位置之外，以免索引被文件同步或 Windows 备份复制到云端。你可以把整个索引导出成 CSV 来阅读，可以单独抹掉人脸数据，可以单独抹掉已保存的文档文本，也可以把整个索引丢掉重建。这些操作都不会碰到你任何一个真实文件。

四个模型，全都不随安装包附带

每个模型都在你第一次使用需要它的功能时才下载，且必须先把体积告知你、由你同意之后才开始，并且逐一对照源码中固定写死的 SHA-256 校验值进行验证。每个下载地址都锁定在上游一个不可变更的提交上，因此取回的字节永远是当初算出校验值的那些字节。

拒绝下载留下的仍是一个功能完整的产品：预设、手动规则构建器、既有习惯的学习、搜索、空间报告、标签和重复检测都完全不需要模型。推理通过 ONNX Runtime 在 CPU 上运行——不注册任何 NPU 或 GPU 执行提供程序，应用也不使用 Windows 内置的 AI 模型。

Stow 不是什么

  • 它不是云相册服务。它不会备份任何东西，不会在设备之间同步任何东西，也不会把你的库复制到你自己的磁盘之外的任何地方。
  • 它不是那种会自己清空的重复文件清理器。什么都不会被销毁；它最多做到的，是在你要求时把多余的副本放进回收站。
  • 它不是自动化守护程序。它会察觉落进受监视文件夹的文件，但不会趁你不注意就把它们归好档。
  • 它不是黑箱。每条建议都附带产生它的规则，每次拒绝都附带解释，而且在任何一个文件移动之前，整份计划都能在电子表格里读完。

它适合谁

适合那些下载文件夹已经变成垃圾场、图片文件夹里堆着三部不同手机十年积累的人。适合 2019 年搭起一套归档方法、漂亮地维持了四个月、如今想把过去五年也照同样方式收好的人。适合必须让 RAW 和 JPEG 待在一起、又需要在不把四万张图片上传给任何人的前提下找出近似重复的摄影师。而贯穿他们所有人的，是那些不愿意仅仅为了整理，就把私人文件送到某家公司服务器上的人。

坦率的局限

推理只在 CPU 上进行，因此对一个大型库的首次索引会比较慢，而且在后台运行时还会被刻意进一步限速。模型的输出可能出错：一条被误解的指令会产出一份错误的计划——这恰恰正是预览和撤销日志存在的理由，也是任何东西都不会在无人看管下被执行的理由。人脸分组仅凭相像程度工作，可能把两个长得像的人并成一组，也可能把同一个人拆到好几组里。
